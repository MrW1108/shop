# 商品选购 Web 应用 PRD

**版本：** 1.1
**产品形态：** React 响应式单页 Web 应用
**目标交付：** 50 分钟内完成可演示的本地版本；如核心体验完成且仍有时间，再部署公开预览版。

## 1. 产品概述

为海外消费者提供一个有个性的多品类精选装备商店。用户无需登录即可浏览包袋、旅行配件、科技配件、饮具和日常随身用品，按类别筛选或搜索、查看商品信息并加入购物车。应用暂时支持英语和简体中文，默认英语；价格统一以美元展示。商品及库存均为模拟数据，不接入真实支付或后端。

### 产品定位

- **概念店：** Wayfarer Supply，精选适用于旅途、通勤和日常生活的多品类装备。
- **体验重点：** 快速发现商品、清楚理解价格和商品特点、随时掌握购物车内容。
- **视觉方向（已确认）：** 全站深色霓虹、动态网格、流动光效和强动效；商品照片、价格与 CTA 保持高对比可读，并支持减少动态效果模式。

## 2. 目标与衡量方式

### 用户目标

用户能在短时间内找到感兴趣的商品，判断是否适合自己，并确认已正确加入购物车。

### 本次交付目标

1. 展示有品牌感的多品类商店首页，包含至少 4 个商品类别和一组完整的模拟商品。
2. 覆盖“浏览/搜索/筛选 → 查看商品 → 加入购物车 → 调整购物车”的核心闭环。
3. 桌面和手机尺寸下均可顺畅操作，关键控件不会被遮挡或溢出。
4. 提供可启动源码、简短交付说明和 2–3 分钟真实操作录屏；线上链接作为加分项。
5. 用户可切换英语/简体中文，所有主要界面和选购流程文案随语言切换。

### 本次不设商业转化指标

本作业没有真实用户流量或支付，不以转化率、订单量作为验收依据；用下文的功能和体验验收标准判断完成度。

## 3. 用户与使用场景

**主要用户：** 使用英语浏览、以美元消费的海外个人消费者；常见入口是手机，也可能在桌面端比较商品。

**核心场景：**

1. 用户打开商店，通过分类或搜索查找一件旅行用品。
2. 用户浏览商品卡片，查看图片、价格、评分和简短卖点。
3. 用户打开商品详情，确认信息后选择数量并加入购物车。
4. 用户打开购物车，调整数量、移除商品并检查小计。

## 4. 产品范围与优先级

### P0：必须完成

- 首页品牌区、主标题/价值说明、搜索框、分类入口/筛选、商品网格。
- 8–10 件模拟商品，至少覆盖 4 个品类；每件包含图片、名称、类别、价格、评分/评价数和简短描述。
- 搜索按商品名称或描述实时过滤；分类筛选可与搜索组合使用；提供“全部”重置选项。
- 商品卡片提供详情入口和明确的加入购物车操作。
- 商品详情展示大图、完整描述、价格、类别/评分、数量选择和加入购物车操作。
- 购物车可打开并显示商品、单价、数量、行小计、总小计；可加减数量、删除商品。
- 购物车数量徽标及金额在用户操作后立即更新；空购物车显示空状态和继续逛商品入口。
- 在桌面和手机窄屏下布局可用，关键流程无需依赖悬停操作。
- 提供英语/简体中文语言切换入口；默认英语，界面文案完整本地化。
- 使用美元格式显示价格；切换语言不改变商品金额或购物车数据。

### P1：有余力时完成

- 商品排序：推荐、价格由低到高、价格由高到低。
- 购物车状态在刷新后保留（使用 `localStorage`）。
- 语言偏好在刷新后保留（使用 `localStorage`）。
- 达到免运费门槛的提示或免运费进度提示；门槛固定为 `$75`，运费只做展示说明，不结算。
- 加入购物车后提供短暂、明确的成功反馈。
- 部署到免费静态托管平台并验证公开链接。

### 不在本次范围

- 注册/登录、真实库存、后端 API、真实订单和支付。
- 地址填写、税费计算、地区切换、多币种和英语/简体中文以外的语言。
- 商品评论提交、复杂筛选、促销码、用户画像或分析埋点。
- 管理后台、SEO 内容体系、生产级监控。

## 5. 信息架构与页面行为

本次采用单页商店，避免 50 分钟内花时间搭建复杂路由。

### A. 商店首页

1. **顶栏：** 品牌标识、品类导航/店铺锚点、语言切换、搜索、购物车按钮与商品数量徽标。语言入口清楚显示 `EN` / `中文`；手机端保留语言和购物车入口，导航可收起或省略。
2. **主视觉区：** 一句清楚的品牌承诺、简短说明和浏览商品行动按钮；表达旅途、通勤与日常多个使用场景，不局限于单一品类。
3. **品类发现与搜索区：** 图形化品类入口或分类标签（如 Bags、Travel、Tech、Drinkware、Everyday Carry）、搜索输入框、当前结果数量；空结果时提示调整条件并提供清除操作。
4. **商品区：** 响应式卡片网格；桌面 3–4 列、平板 2–3 列、手机 1–2 列，按实际可读性决定。
5. **页脚：** 简短配送/退货/客服文案及版权信息，随当前语言显示；明确为演示商店，无需虚构外部服务链接。

### B. 商品卡片与详情

- 卡片中图片、名称、价格和主要操作易于扫读；加入购物车按钮有足够点击面积。
- 点击卡片详情区可打开详情面板/对话框；点击加入购物车按钮只执行加购，不应意外打开详情。
- 详情包含商品大图、名称、价格、评分、描述、数量加减和加入购物车按钮。
- 加购后关闭详情或保留详情均可，但反馈清晰；同一商品再次加购时合并数量。
- 商品名称、类别、描述、徽标和图片替代文本随当前语言切换；语言切换时已选分类仍保持有效。

### C. 购物车

- 桌面端优先采用右侧抽屉；手机端使用全屏面板或接近全屏的底部面板。
- 点击遮罩、关闭按钮或继续购物可关闭购物车；Esc 可关闭当前浮层（若实现为对话框）。
- 数量下限为 1；数量为 1 时减号应禁用，或减至 0 时明确移除，行为须一致。
- 小计为所有商品“单价 × 数量”之和，金额保留两位小数；商品数量徽标按总件数累计。
- 结账按钮不得制造真实支付预期。可以显示“Checkout preview”并明确不可支付，或不提供结账按钮。

## 6. 业务规则与数据

### 商品数据结构

```ts
type Locale = "en" | "zh-CN";

type Product = {
  id: string;
  name: Record<Locale, string>;
  category: Record<Locale, string>;
  price: number; // USD
  rating: number;
  reviewCount: number;
  description: Record<Locale, string>;
  image: string;
  badge?: Record<Locale, string>;
};
```

- 模拟 8–10 件商品，至少覆盖 4 个类别，推荐覆盖 Bags、Travel、Tech Accessories、Drinkware、Everyday Carry。
- 商品图使用稳定的公开图片地址或项目内素材；加载失败时应保留合理的占位背景/替代文字，不得破坏卡片布局。
- 价格为美元，使用统一格式器（如 `$24.00`）。
- 搜索忽略大小写并匹配当前语言的名称、类别和描述；切换语言后保留搜索词，并按新语言重新匹配。
- 搜索与分类条件组合取交集；改变分类不会清空搜索词，清除搜索也不会重置分类。
- 排序只影响当前过滤后的列表。
- 加购同 ID 商品时累加数量；购物车中每种商品仅一行。
- 小计不包含税费或运费。若展示免运费进度，文案需说明这是模拟提示。

## 7. 响应式、可访问性与内容要求

- 最低目标视口：手机宽度 360 px；常规验收宽度 390 px、768 px、1440 px。
- 手机端无横向滚动，弹层和购物车操作区保持在可视区域内；按钮触控面积建议不小于 44 × 44 px。
- 搜索框、分类按钮、数量控件、详情/购物车关闭按钮可用键盘访问，并有可见焦点状态。
- 图片提供描述性 `alt`；图标按钮提供可读标签；文本与背景保持清晰对比。
- 状态变更提供可见反馈，不能只通过颜色传递含义。
- 英语和简体中文文案均应自然、无明显错误；同一界面不得中英混杂或出现没有解释的假链接。

## 8. 验收标准

以下 P0 项全部通过才算核心版本完成。验收以浏览器手动操作为主，不要求接入自动化测试。

### 商品浏览、搜索和分类

- [ ] 首屏可辨认品牌、商店主题、搜索入口和至少一部分商品内容。
- [ ] 初始商品列表展示 8 件或以上商品，覆盖至少 4 个品类；卡片显示图片、名称、美元价格和加购操作。
- [ ] 输入商品名称片段后，列表即时更新为匹配商品；不区分大小写。
- [ ] 输入不匹配内容时出现明确空结果状态，并可清除条件恢复列表。
- [ ] 选择某一分类后仅显示该分类商品；搜索与分类同时生效；选择“全部”可恢复全部类别。
- [ ] 首页提供清楚的多品类入口/导航，点击任一品类可筛选对应商品。
- [ ] 有 P1 排序时，按低价/高价排序结果正确，且搜索/分类仍然有效。

### 多语言

- [ ] 首次访问默认显示英语；顶栏语言控件可切换到简体中文并可切回英语。
- [ ] 切换后导航、搜索提示、分类、商品名/描述、详情、加购反馈、购物车、空状态、按钮、页脚和无障碍标签均使用所选语言，无明显中英混杂。
- [ ] 商品名称、类别、描述、徽标及图片替代文本在两种语言下均有对应内容。
- [ ] 切换语言不会清空搜索词、购物车内容/数量或当前选择的分类；列表根据新语言重新显示和匹配。
- [ ] 价格始终以美元显示：英语使用 `$24.00`，简体中文使用 `US$24.00`（或明确的美元标注）；总价计算不因语言切换改变。
- [ ] 若完成 P1 语言偏好持久化，刷新后沿用上次选择的语言；首次访问且无已保存偏好时默认英语。
- [ ] 页面语言标记随选择更新为 `en` 或 `zh-CN`。

### 商品详情与加购

- [ ] 打开任意商品详情可看到商品图片、名称、描述、类别、评分和价格。
- [ ] 详情数量控件可增加/减少，数量不能变成负数或零（除非零被定义为移除）。
- [ ] 详情加购会将正确商品和数量写入购物车，并立即更新顶部数量徽标。
- [ ] 商品卡片直接加购只执行加购，不误触详情；重复加购同商品会累加数量而非产生重复行。
- [ ] 加购操作有可见成功反馈。

### 购物车

- [ ] 点击购物车入口打开购物车面板；关闭按钮和继续购物操作可关闭它。
- [ ] 购物车显示商品名称、价格、数量以及正确的小计和总小计。
- [ ] 增加/减少数量后总件数、行小计、总小计同步更新。
- [ ] 删除商品后该行消失并重新计算金额；最后一件删除后显示空购物车状态。
- [ ] 空购物车状态包含可理解的提示和返回浏览商品的入口。
- [ ] 若实现刷新持久化，刷新后购物车项目和数量保持一致；无持久化时属于已知限制，不阻断 P0 验收。
- [ ] 不存在看似可完成真实付款、却没有说明的结账操作。

### 电脑与手机体验

- [ ] 在 1440 px、768 px 和 390 px 宽度下检查首页、详情、购物车三类状态。
- [ ] 390 px 下页面无横向滚动，文字和主要按钮不重叠，购物车面板可滚动并能访问全部操作。
- [ ] 桌面端网格与留白比例合理；手机端商品图和操作仍清晰可辨。
- [ ] 不依赖悬停才能发现或操作关键控件；可用键盘操作主要入口和关闭浮层。
- [ ] 商品图片加载失败时页面结构仍完整。

### 源码与交付

- [ ] 源码包含依赖声明、启动命令和必要配置，不包含 `node_modules` 或密钥。
- [ ] 按 README 指令可安装依赖并本地启动。
- [ ] 交付说明包含已实现内容、实际检查的场景、已知问题和主要取舍。
- [ ] 提供 2–3 分钟录屏，真实展示浏览/搜索/筛选、加购、调整购物车，以及电脑和手机宽度表现。
- [ ] 若提供线上链接，未登录状态下可访问；刷新后页面可正常加载，关键加购流程可用。

## 9. 50 分钟执行计划

| 时间 | 工作 | 产出/退出条件 |
|---|---|---|
| 0–5 分钟 | 确认目录和启动方式；搭好 React/Vite 基础与页面骨架 | 本地开发服务器可启动 |
| 5–12 分钟 | 确定高辨识视觉基调、至少 4 类双语商品数据、文案字典、基础排版与响应式容器 | 首页结构和首屏成型 |
| 12–22 分钟 | 实现商品卡片、搜索、分类筛选、语言切换、排序（排序可排在 P1） | 可找到并浏览商品、切换语言 |
| 22–32 分钟 | 实现详情面板、数量选择和加购状态 | 可完成详情到加购 |
| 32–40 分钟 | 实现购物车抽屉、数量编辑、删除、小计和空状态 | 选购闭环成立 |
| 40–45 分钟 | 检查桌面/手机关键视口和交互，修复明显布局问题 | P0 手工验收通过 |
| 45–50 分钟 | 补 README/交付说明；若核心流程稳定则部署或录制演示 | 可交付源码、验证说明与演示素材 |

### 时间压缩原则

- 若时间紧，先保证中英切换、搜索、分类、详情/加购、购物车计算和手机布局；排序、动画、语言持久化优先降为 P1。
- 优先使用少量、职责清楚的 React 组件和本地状态；避免状态库、路由、后端与支付集成。
- 先用稳定的图片素材完成视觉，再修细节；动画和复杂筛选不能挤占核心闭环时间。
- 部署是加分项，只有核心流程已稳定且部署流程顺畅时才进入，避免以部署替代核心验收。

## 11. 风险与假设

- 外部图片服务可能限流或失效；应准备占位样式，并尽量选稳定素材。
- 本地运行依赖当前 Node/npm 环境；README 应提供明确命令。
- 公开免费部署可能有构建或访问限制，线上可用性需实际打开验证后再写入交付说明。
- 本产品默认英语、支持简体中文；两种语言共用美元定价，不实现地区检测和多币种。
- 评分、评价数、配送承诺仅为演示数据，不能表述为真实客户反馈或真实物流保障。

## 12. 多语言实现要求

- 首期仅支持 `en`（英语）和 `zh-CN`（简体中文），默认 `en`；语言切换器在桌面和手机端均可找到。
- 所有界面文案统一从本地字典读取，覆盖导航、分类、搜索提示、详情、加购反馈、购物车、空状态、价格说明、按钮、页脚和可访问性标签；不得出现明显中英混杂。
- 商品名称、类别、描述、徽标和图片 `alt` 文本提供双语内容；评分和评价数等数字不随语言变化。
- 切换语言时保持当前页面、搜索词、购物车商品和数量；当前分类继续选中，并按新语言的类别显示名称。
- 语言偏好写入 `localStorage`，刷新后沿用用户上次选择；首次访问无偏好时使用英语。
- 价格统一为美元。英语使用 `$24.00` 格式，简体中文使用 `US$24.00`，避免用户误以为是人民币。
- 设置页面 `<html lang>` 为 `en` 或 `zh-CN`；语言切换控件有清晰的键盘焦点和可读标签。
- 多语言只处理界面和模拟商品文案，不包含自动翻译、地区检测或其他语言。
